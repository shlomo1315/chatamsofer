# חלוקת חגים — מוקדי חלוקה, שוברים וטעינת כרטיסים

**תאריך:** 20.08.2026 · **סטטוס:** אושר לתכנון

---

## 1. מה נבנה

מערכת בחירת מוקד חלוקה לחגי תשרי: המשפחה בוחרת מוקד (בטלפון או בממשק),
מקבלת שובר מעוצב במייל, וכרטיסה נטען ב-500₪ בנדרים.

**זהו ממשק נפרד לחלוטין מיולדות** — מוקדים נפרדים, הרשאות נדרים נפרדות,
שוברים נפרדים. אין שיתוף נתונים בין השניים.

### מה כבר קיים ואין לבנות מחדש

| רכיב | מיקום | מצב |
|---|---|---|
| שלוחה טלפונית לחגים | `app/api/webhooks/yemot-holiday` | עובד — רישום בלבד |
| עריכת הודעות + ElevenLabs | `yemotHolidayMessages` + `yemot-holiday/generate-voice` | עובד |
| הרשאות נדרים לחגים | `getHolidayNedarimCreds`, `getHolidayLimitedId` | קיים ונפרד |
| טעינת כרטיס | `addTlush` | עובד |
| פריקה / ניתוק | `prikatTlush`, `setMagneticCard` | עובד |
| היסטוריית עסקאות | `getClientCardFull` → `History[]` | עובד |
| מנוע שוברים | `maternityVoucher.ts` + `voucherTextsStore` | עובד |
| זיהוי דרכון | `isPassportId` | קיים |
| רשומות חלוקה | `distribution_recipients` (6,046 שורות) | קיים |

## 2. מודל הנתונים

### `holiday_centers` — מאגר גלובלי

```sql
id            uuid pk
city          text not null      -- "ירושלים"
name          text not null      -- "אזור נווה צבי"
address       text
phone         text
hours         text               -- שעות הפעילות לשובר
region        text not null      -- 'jerusalem' | 'center' | 'north' | 'south'
capacity      integer            -- null = ללא הגבלה
is_active     boolean default true
sort_order    integer
```

**גלובלי ונשמר מחג לחג.** `city + name` מאפשר כמה מוקדים באותה עיר.
`region` מזין את תפריט האזורים בשלוחה.

### `holiday_center_openings` — מה פתוח בחלוקה הזו

```sql
distribution_id   uuid not null
center_id         uuid not null
capacity_override integer
primary key (distribution_id, center_id)
```

**זה מה שהלשונית "פתח/סגור בחירה" מדליקה.** הבחירה מתאפסת בכל חלוקה
חדשה — המשפחה בוחרת מחדש בכל חג.

### `holiday_transactions` — מטמון עסקאות

```sql
id            uuid pk
recipient_id  uuid not null
tx_date       timestamptz
store_name    text not null
amount        numeric
raw           jsonb
unique (recipient_id, tx_date, store_name, amount)
```

**🔴 המטמון אינו מותרות.** `getClientCardFull` נקרא לכל משפחה בנפרד.
ביולדות יש עשרות משפחות וזה עובד; כאן יש ~6,000 — כלומר 6,000 קריאות API
בכל פתיחת מסך, דקות ארוכות. תור רקע מסנכרן למסד, והמסך קורא מהמסד.

### `distribution_recipients` — שלוש עמודות חדשות

```sql
center_id         uuid           -- המוקד שנבחר
center_chosen_at  timestamptz
center_source     text           -- 'phone' | 'portal' | 'admin'
load_status       text           -- 'pending' | 'loaded' | 'failed'
load_error        text
loaded_at         timestamptz
```

### אינדקסים

```sql
create index on distribution_recipients (distribution_id, center_id);
create index on distribution_recipients (distribution_id, load_status);
create index on holiday_transactions (recipient_id, tx_date desc);
```

## 3. הבחירה — שני ערוצים, מקור אמת אחד

```
טלפון (שלוחה 1) ─┐
                  ├─→ lib/holidayCenterPick.ts ─→ center_id
ממשק דיגיטלי    ─┘      אימות · תקרה · נעילה
```

**שני הערוצים עוברים דרך אותה פונקציה.** זה מה שמונע מצב שבו הטלפון
מאפשר מה שהממשק חוסם.

```ts
pickCenter({ recipientId, centerId, source }): Promise<
  | { ok: true }
  | { ok: false; reason: 'locked' | 'full' | 'closed' | 'not_found' }>
```

**נעילה:** אחרי בחירה — נעול. המשפחה אינה יכולה לשנות בטלפון או בממשק;
רק מנהל, מהטבלה. זה מה שההודעה מבטיחה, וזה מה ששומר על תקרות המוקדים.

⚠️ **הנעילה חלה גם על שלוחה 4** ("שמיעת המוקד שנבחר"). היא קוראת בלבד
ואינה מציעה שינוי — אחרת ההבטחה "לא ניתן יהיה לשנות" נשברת בערוץ צדדי.

`center_source` מתעד מאיזה ערוץ הגיעה הבחירה (`phone`/`portal`/`admin`).
⚠️ נחוץ לבירורים: "בחרתי בטלפון ורשום אחרת" אינו ניתן לבדיקה בלעדיו.

## 4. השלוחה הטלפונית

```
שלוחה 1 (תפריט חדש)
  ├─ 1 → רישום           → הזרימה הקיימת, ללא שינוי כלל
  │                         כולל הודעת "סגור" כשהרישום סגור
  ├─ 2 → חיבור כרטיס      → הזרימה הקיימת
  ├─ 3 → בחירת מוקד       → חדש
  └─ 4 → שמיעת המוקד שנבחר → חדש (מי"ז אלול)
```

**🔴 התפריט הוא שכבה בלבד.** מסלולי 1 ו-2 ממשיכים לרוץ בדיוק כמו היום.

### זרימת בחירת המוקד (3)

```
הקשת ת"ז/דרכון → זיהוי → הודעת הסבר (חסימת דילוג 3 שניות)
  → תפריט אזורים (4 אפשרויות)
    → תפריט ערים באזור
      → ירושלים/ב"ב/בית שמש: תפריט מוקדים · שאר: ישיר
        → "לרישום למוקד זה הקש 1 · לחזרה הקש 2"
          → אישור → נעילה
```

**דרכונים:** ספרות בלבד, בלי אותיות. `isPassportId` כבר מזהה; ההקלטה
תסביר זאת.

**אזורים** (במקום 19 ערים בתפריט אחד — 40 שניות האזנה):
- ירושלים והסביבה · מרכז · צפון · דרום

### 26 המוקדים

| אזור | ערים |
|---|---|
| ירושלים | **ירושלים ×5** (נווה צבי · שמואל הנביא · קרית צאנז-בעלזא · מאה שערים · רמות פולין) · ביתר עילית |
| מרכז | **בני ברק ×4** (סקולוב · חזון איש · ויז'ניץ · רחוב ירושלים) · **בית שמש ×2** (רמה ב' · רמה ד') · מודיעין עילית · אלעד · אשדוד · לוד-אחיסמך · נתניה |
| צפון | חיפה · נוף הגליל · צפת · טבריה · רכסים · עפולה |
| דרום | קרית גת · ערד · אופקים |

### תיקוני נוסח

- "ביתר עלית" ← **ביתר עילית**
- "בו קיימת מוקד חלוקה" ← **שבהן קיים מוקד חלוקה**
- `????` בטקסט הדרכונים ← "הקישו את הספרות בלבד, בלי האותיות"

**כל ההודעות ניתנות לעריכה + ElevenLabs**, כמו ביולדות.

## 5. טעינת 500₪

באישור נרשם `load_status='pending'`, ותור רקע מבצע `addTlush`.

- **המסך אינו נתקע** — גם על 500 משפחות
- **כשל באחד אינו מפיל את השאר** — `load_error` לכל שורה
- ניסיונות חוזרים לכשלים זמניים
- עמודת סטטוס: נטען / נכשל / ממתין + מתי

**אישור גמיש:** הכל · קבוצה מסוננת · הוספה ידנית.

## 7. איפוס מלא

```
[איפוס מלא] → תצוגה מקדימה:
                • X כרטיסים פעילים
                • ₪Y עדיין טעונים      ← ההתרעה
                • Z ינותקו
              → אישור מפורש → תור רקע
```

`prikatTlush` + ניתוק הכרטיס המגנטי. **הלקוח נשאר בנדרים** עם היסטוריית
העסקאות — בחג הבא מחברים כרטיס חדש בלי להקליד הכול מחדש.

**ידני בלבד. לעולם לא אוטומטי.**
