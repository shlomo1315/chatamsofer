# תקן הטבלאות של המערכת — מיון וסינון מהכותרת

**תאריך:** 26.08.2026
**מצב:** אפיון לאישור

---

## הבעיה

שתי בקשות נפרדות שנפגשות באותו מקום:

1. **טבלת הצאצאים לא נראית טוב** — העמודות "קופצות" בין טעינות, ורוחב
   עמודת הפעולות משתנה לפי התוכן.
2. **אין מיון וסינון מהכותרת** — כדי לסנן לפי מצב משפחתי צריך לחפש את
   הצ'יפים שמעל הטבלה, ורק חלק מהעמודות בכלל ניתנות לסינון.

הבקשה: **כלל אחד לכל 45 הטבלאות במערכת** — לחיצה על כותרת ממיינת
מלמעלה למטה ולהפך, ובעמודות עם ערכים קבועים (מצב משפחתי, סטטוס, עיר)
נפתחת גם רשימה לבחירת מה להציג. שם פרטי, משפחה, טלפון ומייל — מיון בלבד.

## מה כבר קיים (ולא נבנה מחדש)

| רכיב | מה הוא נותן | כמה טבלאות משתמשות |
|---|---|---|
| `useTableColumns` | בורר עמודות + שמירה ב-localStorage | 22 |
| `useResizableColumns` | גרירת רוחב + גלישת טקסט | דרך ה-hook |

וסינון-לפי-ערך. הן נוספות לתוך `useTableColumns` הקיים, ולא כרכיב מתחרה.

## 🔴 האילוץ שקובע את כל הארכיטקטורה

**טבלת הצאצאים מדפדפת בשרת. כל שאר 44 הטבלאות מחזיקות את הנתונים בלקוח.**

```ts
// lib/beneficiariesList.ts:168 — 50 שורות מתוך 7,066
const from = Math.max(0, (p.page - 1) * p.size)
const to = from + p.size - 1
```

סינון בצד הלקוח על טבלה כזו יסנן **50 שורות מתוך 7,066** ויציג תוצאה
שנראית תקינה לחלוטין. זה בדיוק הבאג שכבר תפס את המערכת פעמיים:

- תקרת 1,000 השורות — אימות ערים ראה 105 מתוך 1,406 וחסם רישום
- כרטיסי הסינון הראו ירושלים 75 במקום 1,695

לכן התקן מגדיר **שני מצבים מפורשים**, והבחירה ביניהם אינה אופציונלית.

## הארכיטקטורה

### שכבה 1 — `lib/tableSort.ts` (טהור, נבדק)

לוגיקת ההשוואה בלבד. בלי React, בלי DOM.

```ts
export type SortDir = 'asc' | 'desc'
export type ColKind = 'text' | 'number' | 'date' | 'enum'

/** השוואה לפי סוג. עברית עם localeCompare, מספרים כמספרים. */
export function compareBy(kind: ColKind, a: unknown, b: unknown): number

/** מיון יציב — שורות שוות שומרות על סדרן. */
export function sortRows<T>(rows: T[], get: (r: T) => unknown,
                            kind: ColKind, dir: SortDir): T[]

/** הערכים הייחודיים בעמודה + מונה, למיון לפי שכיחות. */
export function distinctValues<T>(rows: T[], get: (r: T) => unknown):
  { value: string; count: number }[]
```

**למה טהור:** אותה לוגיקה נדרשת גם בשרת (טבלת הצאצאים) וגם בלקוח.
מימוש כפול היה נסחף — עמודה הייתה ממוינת אחרת בכל מסך.

⚠️ **מיון יציב הכרחי:** בלעדיו שורות בעלות אותו ערך מתחלפות בכל
רינדור, והטבלה "רוקדת" מול המשתמש.

⚠️ **ריקים תמיד בסוף**, בשני הכיוונים. ערך חסר אינו "קטן" — הוא
חוסר ידיעה, ולדחוף אותו לראש ברשימה יורדת מסתיר את מה שהמשתמש חיפש.

### שכבה 2 — `components/ui/TableSortFilter.tsx`

הרחבת `ColDef` הקיימת בשלושה שדות **אופציונליים**:

```ts
export interface ColDef<K extends string = string> {
  key: K
  label: string
  def: boolean
  align?: 'center'
  // ── חדש ──
  /** סוג הערך למיון. ברירת מחדל 'text'. */
  kind?: ColKind
  /** ניתנת למיון בלחיצה על הכותרת. ברירת מחדל: true. */
  sortable?: boolean
  /** ניתנת לסינון לפי ערך. ברירת מחדל: false — נדרשת בחירה מפורשת. */
  filterable?: boolean
  /** חילוץ הערך הגולמי למיון/סינון (כשהתא מרנדר JSX). */
  value?: (row: never) => unknown
}
```

🔴 **`filterable` היא ברירת מחדל `false` בכוונה.** סינון לפי ערך על
עמודת שם או טלפון פותח רשימה של 7,000 ערכים ייחודיים — חסר תועלת וכבד.
המשתמש ביקש מפורשות: שם, משפחה, טלפון ומייל — מיון בלבד.

⚠️ **`value` נדרשת בכל עמודה שמרנדרת JSX.** בלעדיה המיון עובד על
אובייקט React ומחזיר סדר אקראי שנראה כמו מיון.

### שכבה 3 — שני מצבים

```ts
useTableColumns(tableId, COLS, {
  sortFilter: { mode: 'client', rows }        // 44 טבלאות
})

useTableColumns(tableId, COLS, {
  sortFilter: { mode: 'server', state, onChange, options }  // צאצאים
})
```

| | `client` | `server` |
|---|---|---|
| מקור הנתונים | כל השורות בזיכרון | עמוד אחד מהשרת |
| מי ממיין | ה-hook | `order()` במסד |
| אפשרויות הסינון | מהשורות עצמן | מ-`distinct` במסד |
| שמירת המצב | localStorage | פרמטרי URL |

🔴 **חובה לציין `mode`.** אין ברירת מחדל: טבלה שתקבל בטעות `client`
בזמן שהיא מדפדפת בשרת תיצור בדיוק את הבאג השקט שהתקן נועד למנוע.

**אכיפה בלינט:** כלל `eslint-rules/table-sort-mode.mjs` יפיל את הבנייה
על קובץ שמכיל `serverMode` או `range(` יחד עם `mode: 'client'` —
באותה שיטה שבה `no-horizontal-scroll.mjs` תפס 11 מקרים שה-grep פספס.

## ה-UI

לחיצה על כותרת פותחת תפריט אחד, זהה בכל המערכת:

```
┌──────────────────────────┐
│ ↑  מיון מ-א׳ עד ת׳       │   ← תמיד
│ ↓  מיון מ-ת׳ עד א׳       │
├──────────────────────────┤   ← רק כש-filterable
│ 🔍 חיפוש בערכים…         │
│ ☑ נשוי            6,903  │
│ ☑ אלמן               36  │
│ ☐ גרוש              125  │
├──────────────────────────┤
│ בחר הכל · נקה   [החל]    │
└──────────────────────────┘
```

- תוויות המיון לפי סוג: טקסט `א׳→ת׳` · מספר `1→9` · תאריך `ישן→חדש`
- **מונה לצד כל ערך** — המשתמש רואה כמה שורות יסתתרו לפני שהוא מסנן
- **חץ בכותרת** מציין את עמודת המיון הפעילה; **נקודה** מציינת שהעמודה מסוננת
- שורת "מסננים פעילים" מעל הטבלה עם כפתור "נקה הכול" — סינון נסתר בתוך
  תפריט הוא מלכודת: המשתמש רואה 12 שורות מתוך 7,066 ולא יודע למה

⚠️ אין `overflow-x`. התפריט הוא `absolute` מעל הטבלה ולא מרחיב אותה.

## תיקון טבלת הצאצאים (הבקשה הראשונה)

שלושה תיקונים שאינם קשורים למיון:

1. **`table-layout: fixed` + `colgroup`** — כרגע `BeneficiariesTable`
   מרנדרת דרך `DataTable` בלי `tableId`, כלומר בלי המסלול שמייצב רוחב.
   הוספת `tableId="beneficiaries"` מפעילה את כל התשתית הקיימת.
2. **עמודת הפעולות** — `w-px whitespace-nowrap` כבר קיים ב-`DataTable`;
   הבעיה היא שהיא מחוץ ל-`colgroup` ולכן לא נספרת. מטופל ע"י `extraCols: 1`.
3. **רוחב יחסי קבוע לעמודות** — `def` נבחר כך שסכום ברירות המחדל
   נכנס למסך רגיל בלי גלישה.

## מה מחוץ לתחום

- **קיבוץ שורות** ו**סיכומים** — לא התבקשו
